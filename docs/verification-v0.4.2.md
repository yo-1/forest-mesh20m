# 森林資源量メッシュ（20m）境界重複修正・検証記録 v0.4.2

作成日：2026-10-05（日本時間）  
対象：`forest_mesh20m-plugin-v0.4.2.zip`  
SHA-256：`8110d70ecfbfd5b26587fcd9a1d6360c354b9266c30a9b9c7e4d9b9af010c92e`

## 実機試験で確認された問題

v0.4.1 の「20m メッシュを領域ポリゴンに合わせて作成」で、領域境界沿いに欠落するセルがある。既定の排他割当は他の領域にまたがるメッシュを1領域にしか書かず、細分格子による近似判定も細い交差を検出できない。QGIS 3.44.13 の実機画像（2026-10-05）で、境界をまたぐセルが各領域のレイヤに存在する形が正解であることを確認した。

## 修正

- 領域間の重複出力を既定にした。各領域のポリゴンと20m正方形の交差面積が正なら、その領域のレイヤへ正方形全体を出力する。境界で同じ `JF20mID` が別レイヤに存在してよい。
- GDAL の `ALL_TOUCHED=TRUE` で交差セル候補を列挙し、QGIS の幾何演算で正の交差面積を確認する。線・点で接するだけのセルは除外する。`cover_pct` は交差面積 / 400㎡ の四捨五入整数とする。極小の正の交差は採用されても `cover_pct=0` となり得る。
- マスク指定時は領域とマスクの交差部分との正の交差面積で判定する。しきい値が正なら厳密面積の比率で採否を決める。
- 従来の排他割当は選択肢として残し、「旧方式・近似」と明示した。このモードは境界の細い交差を見落とす可能性がある。

変更ファイル：`algorithms/from_polygons_algorithm.py`、`algorithms/rasterize.py`、`core/zone_mesh.py`、`__init__.py`、`metadata.txt`。図郭単位と基本のメッシュ生成の計算部は変更していない。

## この環境での検証

- 境界重複の疑似交差面積試験2件成功。2領域にまたがる同じセルを両方へ出力、極細の正の交差、ゼロ面積除外、しきい値を確認。
- v0.4.1 の書き込み失敗注入8件成功。Python 3.9 構文解析成功。ZIP 19ファイル、CRC成功。
- この環境にQGIS/GDALがなく、新しい厳密判定・マスク交差・性能はWindows実機では未確認。**v0.4.2 は実験版で、領域ポリゴン機能の合格判定には同一入力での再試験が必要。**

## Windows QGISでの再試験

1. v0.4.1 を無効化・削除し、v0.4.2 をZIPからインストールする。領域ポリゴン機能の既定選択が「交差する領域すべてに重複して入れる（推奨・厳密）」であることを確認。
2. 前回の2領域ポリゴンを、マスクなし、しきい値0、同じ系番号で別名のGeoPackageに出力する。赤い境界線に沿って、各領域の20m正方形が途切れず、境界では2レイヤに同じIDのセルが存在することを確認。
3. 細い交差と、線だけで接するセルを選び、前者は採用、後者は除外を確認。`cover_pct` が交差面積に対応するか確認。
4. マスクありでも同様に再試験し、マスク外のセルを除外する。正のしきい値を設定した場合は、それ未満の交差セルが除外されることを確認。
5. 処理時間、件数、QGIS/GDAL版、ログ、境界拡大画像、属性表を記録する。大規模領域での実行時間を測定する。

既存の仕様書・操作マニュアルの「重複なし」「被覆率近似」「既定値」に関する記載は、この実機試験後に更新が必要。
