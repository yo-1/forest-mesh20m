# 機能説明書：森林資源量メッシュ（20m）生成プラグイン

バージョン 0.4.2（実験版）／対象 QGIS 3.34 以降／ライセンス GPL-2.0-or-later／リポジトリ https://github.com/yo-1/forest-mesh20m

このプラグインは、森林資源量集計メッシュ（20m）の**格子だけ**を作る QGIS プラグインです。属性の集計（本数・樹高・材積など）は行いません。準拠仕様は、森林情報に関するオープンデータ標準仕様書 Ver.2.1【航空レーザ森林資源解析データ編】と、森林資源データ解析・管理標準仕様書 Ver.3.1（いずれも令和8年8月版）です。

## 1. 提供する機能の一覧

機能は 3 つの Processing アルゴリズムとして、Processing ツールボックスの「森林資源量メッシュ（20m）」グループに登録されます。

| 番号 | アルゴリズム名                                                 | 使いどころ                                                       | 出力                                 | 実機確認                                       |
|------|----------------------------------------------------------------|------------------------------------------------------------------|--------------------------------------|------------------------------------------------|
| ①    | 20m メッシュを作成（国土基本図図郭ベース）                     | 小さな範囲のメッシュ・格子線を 1 レイヤで作る                    | 1 レイヤ（一時／ファイル）           | 確認済み（v0.2.1、QGIS 3.44.11）               |
| ②    | 20m メッシュを図郭ごとに出力（GeoPackage）                     | 広い範囲を、ファイル単位図郭ごとの GeoPackage に分けて出力する   | 図郭ごとに 1 ファイル                | 出力は確認済み。「読み込む」オプションは未確認 |
| ③    | 20m メッシュを領域ポリゴンに合わせて作成（領域ごとに別レイヤ） | 流域・県などのポリゴン、マスクに合わせて、領域ごとにレイヤを作る | 1 つの GeoPackage に領域ごとのレイヤ | **未実行**（v0.4 新機能）                      |

## 2. 共通の機能

### 2.1 メッシュの付番

- メッシュは、各平面直角座標系の原点を基準にした 20m の正方格子です。系の原点を中心に、南北 ±300 km、東西 ±160 km を覆います。

- すべてのメッシュに 12 桁の ID（JF20mID）を付けます。構成は、系番号（2 桁）、50000 区画の行・列の英字（2 文字）、5000 区画の行・列（数字 2 桁）、20m の行・列（数字 6 桁）です。例：08LE00000000 は系VIII の LE 区画の最初のメッシュです。

- 位置から ID を求める計算は、メッシュ境界上の点を南側・東側のメッシュに入れる規則（floor 方式）で行います。この規則は仕様書に記載がなく、本実装の仮定です。

### 2.2 座標系

- 系番号（I〜XIX）と測地系（JGD2011／JGD2000）を選ぶと、対応する平面直角座標系で出力します。

- EPSG コードは規則で作っています。JGD2011 は 6668＋系番号、JGD2000 は 2442＋系番号です。実機で確認できたのは系VIII・JGD2011（EPSG:6676）だけです。

- JGD2024 は未対応です。仕様書では JGD2011 からの名称変更で座標の数値は引き継がれるため、メッシュの番号・位置は変わりません。QGIS／PROJ に JGD2024 のコードが入った時点で追加します。

### 2.3 属性（暫定名）

| 属性名      | 型           | 内容                                             | 出力するアルゴリズム      |
|-------------|--------------|--------------------------------------------------|---------------------------|
| JF20mID     | 文字列（12） | メッシュ ID                                      | ①②③（ポリゴン・ポイント） |
| file_zukaku | 文字列（5）  | ファイル単位図郭名（例 08LE1）                   | ①②③（ポリゴン・ポイント） |
| cover_pct   | 整数         | 被覆率［%］（400㎡に対する対象面積の割合。既定の重複出力は厳密な交差面積、旧方式は近似） | ③のみ                     |
| kind        | 文字列（3）  | row（東西線）／col（南北線）                     | ①のライン                 |
| boundary_no | 整数         | 全域メッシュ番号での線の番号                     | ①のライン                 |

属性名はまだ正式に決まっていません（Issue \#5）。algorithms/common.py の定数で変更できます。

### 2.4 安全のための動作

- ①は、メッシュ数が上限（既定 100 万）を超えると、何も作らずに中止します。

- ②③の GeoPackage 出力は、同名のファイルがあると、何も書き込まずに中止します（上書きしません）。

- ②は、作成するファイル数の上限（既定 100）を超えると中止します。

- ③の一時レイヤ出力は、メッシュ数の合計が上限（既定 30 万）を超えると中止します。

- 系の有効範囲（南北 ±300 km、東西 ±160 km）を超える範囲・領域は、エラーにします。

- 処理中にキャンセルすると、書きかけのファイルは不完全なまま残ります。①②③とも警告をログに出しますので、そのファイルは使わないでください（v0.4.1 で①にも警告を追加）。
- 出力先への書き込みに失敗した場合は、正常完了とせずエラーで中止します（v0.4.1）。

## 3. 各アルゴリズムの機能

### 3.1 ① 20m メッシュを作成（国土基本図図郭ベース）

範囲を指定して、その範囲にかかる 20m メッシュを 1 つのレイヤに作ります。

- 範囲の指定は、「作成範囲」か「ファイル単位図郭名」（例 04HE2、複数可）のどちらか一方です。

- 形状は、ポリゴン（メッシュ 1 枚 = 1 フィーチャ）、ポイント（メッシュ中心点）、ライン（格子線）から選びます。

- ラインは範囲全体を通る線で、メッシュ数に比例しないため、広い範囲でも軽く作れます。

- 出力先は、Processing の通常の出力先（一時レイヤ、ファイルなど）を選べます。

- 1 つのファイル単位図郭は 75 万メッシュです。既定の上限 100 万件を超える範囲は中止します。

### 3.2 ② 20m メッシュを図郭ごとに出力（GeoPackage）

ファイル単位図郭（50000 図郭を 2×2 に分けたもの。15 km × 20 km）ごとに、別々の GeoPackage を出力します。

- ファイル名は仕様書 表2.1 に沿って fr_mesh20m\_{図郭}\_{整備年}.gpkg です。レイヤ名はファイル名から拡張子を除いたものです。

- 範囲は「作成範囲」か「ファイル単位図郭名」のどちらか一方です。「作成範囲」では、端の図郭を範囲で切り取ります。「図郭全体を出力する」をオンにすると、図郭全体を出力します。

- 図郭ごとに順次書き込むため、メモリ使用量は 1 図郭分（最大 75 万メッシュ）に収まります。

- 整備年は必須です（誤った年がファイル名に入るのを避けるため、既定値はありません）。

- 「出力後にレイヤを読み込む」で、完了したファイルを QGIS に読み込めます（10 ファイルまで。既定はオフ）。

### 3.3 ③ 20m メッシュを領域ポリゴンに合わせて作成（領域ごとに別レイヤ）

流域・県・解析範囲などのポリゴン 1 件につき、メッシュのレイヤを 1 つ作ります。手作業での選択・マージで起きる取りこぼしを、条件を決めた自動処理に置き換えるための機能です。

| 機能                 | 内容                                                                                                                                                                   |
|----------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 領域ごとに別レイヤ   | 領域レイヤの地物 1 件 = 出力レイヤ 1 つ。レイヤ名は指定した属性値から作ります（未指定なら zone001 などの連番）                                                         |
| マスク               | 地域森林計画対象林などを指定すると、「領域 ∩ マスク」にかかるメッシュだけを作ります                                                                                    |
| 被覆率のしきい値     | メッシュ 400 ㎡ に対する対象面積の割合がしきい値以上のメッシュを採用します。0 は、正の面積で重なれば採用です（線や点で接するだけのセルは除きます）                    |
| 判定方法             | 既定は厳密な交差面積で判定します（v0.4.2）。旧方式（1 つの領域にだけ割り当てる）を選んだときだけ、メッシュを n×n に細分した格子に領域をラスタ化して被覆率を近似します。細分数は旧方式でのみ使います |
| 領域をまたぐメッシュ | 既定は「交差する領域すべてに重複して入れる」です（v0.4.2）。領域（マスクがあれば領域∩マスク）と正の面積で交差する 20m 正方形を、領域ごとに全体で出力します。境界のセルは隣り合う領域の両方のレイヤに入り、同じ JF20mID が複数のレイヤに存在します。「1 つの領域にだけ割り当てる（旧方式・近似）」も選べますが、境界の細い交差を見落とすことがあります                      |
| 出力先               | GeoPackage（推奨。1 ファイルに領域ごとのテーブル）／一時レイヤ（メッシュ数の合計に上限）                                                                               |
| 空間索引             | マスクの空間索引をメモリ上で自動作成します。事前に索引を作る作業は要りません。GeoPackage 出力にはファイル側の索引が自動で付きます                                      |
| 検査用のログ         | 領域ごとに、採用数、被覆率の分布、しきい値で落とした面積、他の領域へ割り当てた面積を出力します。マスクなしのときは、領域面積とラスタ化面積が 1% 以上ずれると警告します |
| 入力の保護           | 無効なジオメトリは修復（makeValid）して使い、修復できないものは警告して除外します。領域レイヤの CRS が系と異なる場合は変換します                                       |

既定の重複出力は、厳密な交差面積で採否と被覆率を決めます。被覆率（cover_pct）は 交差面積÷400㎡ の四捨五入の整数なので、極小の交差は採用されても 0 になることがあります。旧方式（1 つの領域にだけ割り当てる）は近似です。細分数 5 では被覆率の分解能が 4% で、サンプル点にかからない重なりは、しきい値 0 でも検出されません。

## 4. できないこと（対象外）

- 属性の集計（本数、樹高、材積など）。

- 行政コード・森林簿の付番、樹種の判定（仕様書 Ver.3.1 の付番規則は未実装）。

- 複数の系にまたがる地域の自動切り分け（北海道、東京都、鹿児島県、沖縄県）。系適用区域図を使う機能として v0.5 で予定しています。

- ラスタを範囲として使うこと（v0.6 予定）。

- JGD2024 の EPSG コードでの出力。

- スタイル（QML）、ベクトルタイルの出力。
