# 仕様書：森林資源量メッシュ（20m）生成プラグイン

バージョン 0.4.2（実験版）／対象 QGIS 3.34 以降（動作確認は 3.44.11・Windows。③の重複出力は 3.44.13・Windows で小範囲を確認）／GPL-2.0-or-later

本書は、プラグインの入出力・計算規則・内部構成を定義します。機能の概要は機能説明書、操作手順は操作マニュアルを参照してください。「仮定」「未検証」と書いた箇所は、仕様書や実機で確認できていない事項です。

## 3. メッシュの仕様

### 3.1 格子

- セルは 20 m × 20 m。各系の原点を基準にした全域メッシュ番号 (row, col) で位置を表す。
- 座標の約束（測量座標系）：northing ＝ X 軸（北が正、QGIS の y）、easting ＝ Y 軸（東が正、QGIS の x）。
- 格子の北西端は northing ＝ +300,000 m、easting ＝ −160,000 m。(row, col) ＝ (0, 0) がこの角のセル。
- row は北から南へ 0〜29,999（20 m × 30,000 ＝ 600 km）、col は西から東へ 0〜15,999（20 m × 16,000 ＝ 320 km）。

```text
row = floor((300000 - northing) / 20)
col = floor((easting + 160000) / 20)
```

- 有効範囲は northing ∈ (−300000, 300000]、easting ∈ [−160000, 160000)。範囲外・非有限値はエラーにし、黙って丸めない。
- 【本プラグインの仕様】境界線上の点は、南側・東側のメッシュに入れる（上式の floor）。標準仕様書に記載がないため、本プラグインが採用して固定した規則である。

各セルは、東西方向が [西辺, 東辺)（西辺を含み東辺を含まない）、南北方向が (南辺, 北辺]（北辺を含み南辺を含まない）である。
南北は、北が正の northing で見ると下限が開いた区間（南辺を含まない）になる。row が北から南へ増える向きで見れば、row 方向の [row 上端, row 下端) と同じ向きの半開区間である。

規則の文面【本プラグインの仕様】:

1. セルの境界線上の座標は、南側および東側のセルに帰属させる。境界が東西の線なら東側、南北の線なら南側のセルとする。2 つの線の交点（セルの角）にある点は、その点を北西角とするセルに帰属する。
2. 座標からセル番号への変換は、倍精度浮動小数点で除算した結果に floor 演算を適用して行う（上式）。
3. セルの座標は、整数の行・列から、整数値どうしの加減乗算だけで算出する。値は float64 で厳密に表せる範囲（絶対値 2⁵³ 未満）に収まるため、出力するセルの頂点座標・辺長・面積（400 ㎡）に浮動小数点誤差は生じない。

保証の範囲外: 2 の座標→番号の変換（浮動小数の除算。境界ちょうど・±1e-9 m の確認では不一致 0 件だが、整数演算ではない）、入力範囲を別の座標系から変換する際の誤差、③の旧方式（排他割当）の被覆率（近似）、③の極小の交差（面積 1e-9 ㎡ 以下）の判定、出力後に他のツールで座標変換・加工した結果。

境界付近の点の所属【本プラグインの仕様】（実装と単体テストで固定）:

| 入力 | 東西方向（easting＝100020.0 が境界） | 南北方向（northing＝50020.0 が境界） |
|---|---|---|
| 境界ちょうど | 東側のセル（col 13001） | 南側のセル（row 12499） |
| 境界から 1e-9 m だけ西・南へ | 西側のセル（col 13000） | 南側のセル（row 12499） |
| 境界から 1e-9 m だけ東・北へ | 東側のセル（col 13001） | 北側のセル（row 12498） |

- セルの座標は整数の行・列から整数演算で作る（float64 で厳密）。逆変換は浮動小数の除算（floor）で、境界ちょうど・±1e-9 m の確認では不一致 0 件。厳密な整数演算化は将来課題。

### 3.2 階層とメッシュ ID（JF20mID、12 桁）

| 階層 | 大きさ | 20m メッシュ数 | 表記 |
|---|---|---|---|
| 地図情報レベル 50000 | 南北 30 km × 東西 40 km | 1500 × 2000 | 縦 A〜T（20 区画）、横 A〜H（8 区画） |
| 地図情報レベル 5000 | 3 km × 4 km（50000 の 10×10 分割） | 150 × 200 | 数字 2 桁（行・列） |
| 20m メッシュ | 20 m × 20 m | － | 数字 6 桁（行 3 桁・列 3 桁） |

```text
JF20mID = 系(2桁) + 行英字 + 列英字 + 5000の行(1桁) + 5000の列(1桁) + 行(3桁) + 列(3桁)
例: 08LE00000000 = 系VIII、LE 区画の最初のメッシュ
```

行英字は row ÷ 1500、列英字は col ÷ 2000 の商で決まる（行英字は A〜T で I・O を含む）。5000 の行・列は 50000 区画内での剰余を 150／200 で割った商、末尾 6 桁は 5000 区画内での剰余。

### 3.3 ファイル単位図郭

- 50000 区画を 2 × 2 に分けたもの（15 km × 20 km、750 × 1000 ＝ 75 万メッシュ）。名称は 系(2桁) + 行英字 + 列英字 + 枝番(1〜4)、例 08LE1。
- 【仮定・未検証】枝番は 1＝北西、2＝北東、3＝南西、4＝南東。公式ビューアとの照合は未実施（Issue #2）。
- 図郭名は大文字のみ受け付ける（入力は全角→半角、小文字→大文字に正規化してから解析）。

## 6. ③の採用規則

### 6.0 既定：重複出力（厳密。v0.4.2）

1. 候補セルを GDAL の ALL_TOUCHED＝TRUE のラスタ化で列挙する（領域、マスクがあれば領域∩マスク）。
2. 候補ごとに、QGIS の幾何演算で領域との交差面積を求める。線や点で接するだけの候補は面積が 0 なので除外する。
3. 採用条件：交差面積 ＞ 0 かつ 交差面積÷400 ×100 ≧ THRESHOLD。
4. cover_pct ＝ round(交差面積÷400 ×100)。極小の交差は採用されても 0 になりうる。
5. 採用したセルは、領域ごとのレイヤに正方形の全体を出力する。別の領域との所有判定は行わない。境界のセルは複数のレイヤに入り、同じ JF20mID が複数のレイヤに存在する。

実機確認：Windows・QGIS 3.44.13 で、2 領域（マスクあり、しきい値 0%）の出力を入力から再計算した期待値と照合し、欠落 0、余分 0、ID 重複 0、被覆率の不一致 0 であった（PR #12 のコメント、2026-10-06）。未確認：面積が 1e-9 ㎡ 以下の極小の交差、しきい値 0% 以外、書き込み失敗の画面表示、広域処理の時間とメモリ。

### 6.1 旧方式（排他割当）の被覆率の近似

以下の 6.1〜6.2 は、「1 つの領域にだけ割り当てる」を選んだときだけ使う。

1. 帯（行方向に区切った範囲）ごとに、領域（とマスク）を GDAL で 1 セル＝ n×n サンプルの格子にラスタ化する。ピクセル中心がポリゴン内なら 1（ALL_TOUCHED＝FALSE）。
2. 領域のサンプル ＆ マスクのサンプル（論理積）を対象にする。
3. セル内の 1 の個数を count、被覆率 ＝ count ÷ (n×n) × 100 [%]。セル中心は中央のサンプル（n は奇数）。
4. 被覆率の分解能は 1÷(n×n)（n＝3 で 11%、n＝5 で 4%、n＝9 で 1.2%、n＝15 で 0.44%）。サンプル点にかからない重なりは検出されない（量子化幅であり、実面積の下限ではない）。

### 6.2 採用と所有

- 採用条件：count ≥ 1 かつ 被覆率 ≥ THRESHOLD。THRESHOLD ＝ 0 は「1 サンプルでも重なれば採用」。
- 優先度キー ＝ (セル中心が領域内なら 1000 、そうでなければ 0) ＋ count。採用不可なセルは 0。
- 「1 つの領域にだけ割り当てる」では、キーが最大の領域が所有する。同点は領域の番号（レイヤ内の並び順）が小さい方。最大キーの領域は必ず所有者になるため、採用可能なセルがどの領域にも入らないことはない（単体テストで確認）。
- 既定の「重複して入れる」は 6.0 の規則による。
- 【注意】このとき領域の中心点判定は、仕様書 Ver.3.1 の「行政情報をメッシュの中心点で付番する」考え方と整合する。

### 6.3 ログに出す検査情報

- 領域ごとに、採用メッシュ数、採用セル内の対象被覆面積 [ha]（近似。セル全体の面積は採用数×0.04 ha）、被覆率の分布（境界セル。区間 0〜10、10〜25、25〜50、50〜75、75〜90、90〜100% 未満、100%）。
- しきい値未満で採用しなかった面積、他の領域へ割り当てた面積。
- マスクなしのとき、領域面積とラスタ化面積が 1% 以上ずれると警告。
- 採用メッシュが 0 件のレイヤは警告。

### 6.4 内部の帯分割

1 帯のセル数は、上限 200,000 セルかつサンプル総数 8,000,000 以下（細分数 5 で 200,000 セル、細分数 15 で約 35,500 セル）。帯の分割は結果を変えない（単体テストで確認）。

## 7. 出力データ仕様

| 項目 | ① | ② | ③ |
|---|---|---|---|
| 形式 | Processing の出力先 | GeoPackage（1 図郭 1 ファイル） | GeoPackage（1 ファイルに領域ごとのテーブル）または一時レイヤ |
| ファイル名 | ユーザー指定 | fr_mesh20m_{図郭}_{整備年}.gpkg | ユーザー指定（.gpkg でなければ追記） |
| レイヤ名 | Processing の既定 | ファイル名から拡張子を除いたもの | 接頭辞＋属性値（記号・空白は _ に置換、最大 60 文字、重複は _2 _3） |
| ジオメトリ | ポリゴン／ポイント／ライン | ポリゴン／ポイント | ポリゴン／ポイント |
| 座標系 | 選んだ系・測地系 | 同左 | 同左 |
| 属性 | JF20mID, file_zukaku（ラインは kind, boundary_no） | JF20mID, file_zukaku | JF20mID, file_zukaku, cover_pct |
| 文字コード | － | UTF-8 | UTF-8（GeoPackage） |
| 空間索引 | 出力先に依存 | GeoPackage の R-tree（実ファイルで確認済） | GeoPackage の R-tree（②と同じ規則。③での確認は未実施） |

- ポリゴンはセルの矩形、ポイントはセル中心。行・列順（北から南、各行で西から東）で出力する。
- 属性名は暫定（Issue #5）。Ver.3.1 の管理用 Shapefile（SHIFT_JIS、10 文字制限）と Ver.2.1 の GeoPackage で要件が異なる点に注意。
- cover_pct：既定の重複出力では round(交差面積 ÷ 400 × 100)（6.0）。旧方式では round(count × 100 ÷ (n×n)) の近似値で、厳密な面積比ではない。

## 8. エラー・制限の仕様

| 条件 | 動作 |
|---|---|
| 「作成範囲」と「ファイル単位図郭名」を両方指定、またはどちらも未指定（①②） | エラー |
| 範囲・領域が系の有効範囲（南北 ±300 km、東西 ±160 km）を超える | エラー（③は領域名付き） |
| ファイル単位図郭名の形式不正 | エラー |
| ①のメッシュ数が MAX_CELLS を超える（ポリゴン／ポイント） | 作らずに中止 |
| ②のファイル数が MAX_FILES を超える | 作らずに中止 |
| ②の整備年が西暦 4 桁でない | エラー |
| ②③の出力先に同名ファイルがある | 何も書かずに中止（上書きしない） |
| ③で GeoPackage 出力なのに出力ファイルが空 | エラー |
| ③の一時レイヤが TEMP_MAX を超える | 処理を中止（それまでに作った一時レイヤは読み込まれない） |
| ③で有効な領域が 1 件もない | エラー |
| ③の領域のジオメトリが無効 | makeValid で修復。修復できないものは警告して除外 |
| ③で採用メッシュが 0 件の領域 | 空のレイヤを作り、警告 |
| 処理中のキャンセル（①②③） | 出力は不完全なまま残り、警告を出す（①は v0.4.1 で追加） |
| 出力先への追加・確定の失敗（①②③） | addFeatures / flushBuffer の失敗を検出し、lastError 等を含むエラーで中止（v0.4.1。偽 qgis での配線確認のみ、実機未確認） |

```text
    create_mesh_algorithm.py       ①
    split_by_zukaku_algorithm.py   ②
    from_polygons_algorithm.py     ③
    rasterize.py             GDAL によるラスタ化（③）
    outputs.py               GeoPackage 複数レイヤ・一時レイヤ（③）
  core/                      QGIS 非依存（numpy のみ）
    zukaku.py  grid.py  crs.py  coverage.py  zone_mesh.py  naming.py
tests/                       core の単体テスト（unittest）
```

- 設計方針：計算ロジックは core（QGIS 非依存）に置き、QGIS 側は入出力と配線に限る。QGIS の版差は qgis_compat.py に閉じ込める。
- ③は、ラスタ化を「帯ごとのサンプル配列を返す関数」として core に渡す。このため被覆率・しきい値・所有規則は GDAL なしでテストできる。
- 細分ラスタ・マスクの取得は領域を系の座標へ変換した後に行う。マスクの空間索引はメモリ上（QgsSpatialIndex）。帯ごとに索引で候補を絞り、ジオメトリは FID 指定で取得する。

## 10. 性能・非機能要件

- ①②の書き込み速度は、実測 38,514 件を約 0.55 秒。これからの推定で、1 図郭（75 万件）は約 11 秒（推定）。
- ③の速度・メモリは未計測。実機で、75 万セル規模と山梨県規模で計測して確定する（Issue #6）。
- メモリの目安（設計上の上限）：②は 1 図郭分、③は 1 帯分のサンプル（8 MB 以下）とマスク索引。
- セキュリティ：秘密情報を扱わない。ネットワーク通信なし。ファイルは指定された出力先にのみ作る。既存ファイルは上書きしない。
